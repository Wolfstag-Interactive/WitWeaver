Detailed Description

Defines how a prefab-based character is displayed in a WitWeaver conversation.

A shared expression pool lives at the asset level. Individual PrefabCharacterConfigurationEntry items can optionally override it with entry-specific expression mappings.

Each configuration entry names a prefab to use as a spawn fallback when the character is not found in the scene registry, and the WitWeaverCharacterBehaviour ScriptableObjects that govern world-space placement.

At runtime, WitWeaver always checks the scene registry by character ID first before spawning from the entry prefab. No explicit source-mode flag is required.

◆ ProcessExpression()

override object WolfstagInteractive.WitWeaver.PrefabCharacterRepresentationData.ProcessExpression ( string  expressionId)

Returns expressionId unchanged (including null/empty), by design: prefab visuals are bound by the spawned display, not resolved here.

The spawner (WitWeaverPrefabRepresentationSpawner.ResolveCharacter) passes the ID to IWitWeaverCharacterDisplay.ApplyExpression, which looks the GUID up on the bound representation. Consumers rendering prefab representations should route through the spawner/display path instead of calling this method.
